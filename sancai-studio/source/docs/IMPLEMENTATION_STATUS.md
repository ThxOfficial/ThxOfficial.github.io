## 关键实现决定

- 数据库名 `sancai-studio`，活动项目 key 为 `sancai-studio:active-project`。不访问旧 `caomu-rubu` 数据库。
- 模板/渲染版本与文件 schema 分开保存。新项目类型为 `sancai-project`，不接受草木项目。
- 结果渲染读取 `firing.design`，不是临时编辑状态；确定性纹样和流动使用固定种子。
- 奶白釉和素胎都不透明，釉层 coverage 独立；素胎无釉处仍是哑光。
- 首版 `ensureFiredArtifact` 主要使用内存缓存；本次已接入 IndexedDB 成品与缩略图 Blob 缓存，详情见下方第二轮记录。
- 原创 path 分区支持四形象；人物脸/手作为保护区，默认不参与自由涂釉。
- 保存写入排队、乐观冲突检查、删除标记；30 步历史、整笔提交，750ms 自动保存。
- 模板联合轮廓统一路径方向，减少重叠形状相抵造成透明洞。

## 第二轮：参考风格重绘与功能补齐（2026-10-25）

### 已完成

- 四款第二版素坯：骏马、行驼、拱手文官、守护俑。更修长的比例、连续的可见轮廓、侧面小眼、鬃尾细线、毯边流苏、衣褶与甲饰。
- 不再给马腿与躯干之间画整块闭合接缝。区域遮罩与可见轮廓分离，保留 12/12/10/12 个可涂色大区。
- templateVersion 支持 1/2。创建新作使用第二版，读取/导入旧作仍使用第一版。
- 增加“用新造型再创作”：独立副本保留配色、釉量和参数纹样，清除不适用于新轮廓的笔触；普通复制仍保留旧模板。
- 成品与作品集缩略图写入 IndexedDB，内容签名包含设计、风格、种子、模板与输出尺寸；SHA-256 生成缓存键。缓存最多 80 项/约 48MB，按最近访问清理，失败时回退重绘。
- 缓存不承担项目数据保存职责，不可用时仍可制作与导出。
- 笔刷以起笔时颜色/尺寸为准，合并输入采样，长笔触逐步抽稀后继续保留末端，避免只画前 256 点。
- 临时笔刷和高亮使用实际可见区域遮罩，扣除上层鞍毯、饰物和受保护的面部；取消/丢失捕获/按 Escape 不提交半笔。
- 纹样主色可直接通过色块修改，修正原先选色不立即改变已有纹样的问题。
- 高分辨率渲染分块使用消息任务让出主线程，移除逐块依赖后台计时器的等待方式；不将浏览器工具的整次等待当作应用性能测量。
- 修复子目录预览脚本 root 含尾部分隔符时误拒绝 JS/CSS 的问题。
